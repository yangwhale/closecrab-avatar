# 参考图和音频怎么选 —— 实测出来的

> 数字人的口型准不准，**绝大部分由你给的那张参考图决定**，跟推理管线基本无关。
> 这一页是 2026-09-19 的一次消融实验的结果：22 个条件，每次只改一个变量，
> 其余（模型、seed、步数、LoRA、分辨率、音频）全部锁死。

## 先看结论

```
脸在画面里越大越清楚 ── 这一条压倒其他所有条
  ↓
正脸，不要侧脸  ──────── 侧过去就基本废了
  ↓
光要平，别有硬阴影  ───── 半边脸在暗处会掉一半
  ↓
剩下的（眼镜/字幕条/压缩/手）都是小钱
```

**一句话：拍一张证件照那样的正面头肩像，光打匀，嘴闭上。**

## 照着抄

| 要 | 不要 |
|---|---|
| **头肩特写**，脸占画面短边的一半以上 | 全身、半身、大远景 |
| **正对镜头**，视线看镜头 | 侧脸、低头、仰头 |
| **柔和均匀的光**，两边脸一样亮 | 单侧硬光、逆光、欠曝 |
| **嘴自然闭合**，唇线清楚 | 从说话视频里截的张嘴帧 |
| **素净背景** | 杂乱房间、背景里还有别人 |
| 真人照片；插画风也行 | 三维渲染风 |
| 下巴和嘴**完全露出来** | 手托腮、麦克风挡嘴、高领遮下巴 |
| 干净的原图 | 烧死的字幕条、水印、UI 条 |

音频那一侧几乎不用管，见[下面](#三音频几乎不用操心)。

## 一、判据和它的噪声底

量的是**嘴张多大 ↔ 声音多响**的互相关峰值，直接对着生成好的成片量：
Haar 检人脸 → 取脸框下三分之一当嘴区 → 嘴区暗像素比例当「张口」。

**这把尺子校准过**：把音频人为挪 ±200 ms，读数跟着挪 ±200 ms，一毫秒不差。

**噪声底**：同一配置跑 4 遍得 0.124 / 0.130 / 0.131 / 0.140，**极差 0.016**。
下文所有「变差了多少」都按这条线判，小于 0.016 的不算差别。

> ⚠️ 第一版这把尺子是错的：没有人脸检测，直接找「整帧里最活跃的小块」，
> 结果**框在手上** —— 说话的人手的动作比嘴大。把热力图存下来一看就露馅了。
> **每一条结论都把框画出来存了图**，不看图不信读数。

## 二、参考图：15 个条件

音频全程固定用同一段（我们自己的 TTS），所以比的纯粹是图。

| 条件 | 生成后脸宽 | 相关 | Δ 基线 |
|---|---|---|---|
| **【基线】干净头肩 · 正面 · 闭嘴 · 柔光 · 素背景** | 229 px | **0.313** | — |
| 动漫插画风 | 241 px | 0.294 | −0.020 |
| 底部烧死字幕条 + 水印 | 230 px | 0.292 | −0.021 |
| 手挡住下巴 / 嘴角 | 227 px | 0.288 | −0.025 |
| 低清 + 重 JPEG 压缩 | 229 px | 0.285 | −0.028 |
| 戴眼镜 | 260 px | 0.274 | −0.040 |
| 张着嘴（从说话视频里截的） | 226 px | 0.255 | −0.058 |
| 暗光 / 欠曝 | 235 px | 0.228 | −0.086 |
| 三维渲染风 | 233 px | 0.207 | −0.107 |
| **强侧光（半边脸在阴影里）** | 243 px | 0.169 | **−0.144** |
| 〔构图〕机房半身 | 123 px | 0.151 | −0.163 |
| 〔对照〕从采访视频里截的竖版人像 | 156 px | 0.140 | −0.173 |
| 〔构图〕全身 | 106 px | 0.102 | −0.211 |
| 杂乱背景 + 背景有别人 | 139 px | 0.119 | −0.194 |
| **侧脸 45°** | 201 px | **0.069** | **−0.244** |

### 脸的大小压倒一切

15 个条件里，**脸宽和得分的皮尔逊相关 r = 0.719**。

```
106 px → 0.102      全身
123 px → 0.151      半身
156 px → 0.140      采访视频截图
229 px → 0.313      头肩特写
```

所以「换一张更好的图」第一步不是换人、不是换背景，是**把脸拍大**。
线上那张换成同一个人的头肩特写，读数从 0.140 涨到 0.313，**翻了一倍多**。

### 脸一样大时，才看得出其他属性

把脸宽锁在 226–260 px 这一档，剩下的差异才是那个属性本身的：

| 属性 | 代价 | 说明 |
|---|---|---|
| 侧脸 45° | **−0.244** | 脸只小了 12%，掉了 78% —— 绝大部分不是尺寸，是朝向 |
| 强侧光 | **−0.144** | 脸比基线还大，照样腰斩。**光比构图还敏感** |
| 三维渲染风 | −0.107 | |
| 暗光 | −0.086 | |
| 张着嘴 | −0.058 | 从说话视频里随手截一帧的典型代价 |
| 戴眼镜 | −0.040 | 比想象中小 |
| 低清压缩 | −0.028 | 比想象中小 |
| 手挡下巴 | −0.025 | 比想象中小 |
| 字幕条 + 水印 | −0.021 | 刚过噪声线 |
| 动漫插画风 | −0.020 | **几乎不掉** |

两个反直觉的：

- **动漫风几乎不掉（−0.020），三维渲染风掉得明显（−0.107）。**
  不是「非真人就不行」—— 扁平的赛璐璐动画反而很稳，
  吃亏的是那种半写实的 CG 质感。
- **眼镜、压缩、水印这些看起来很脏的因素都是小钱**，
  真正致命的是朝向和光。

## 三、音频几乎不用操心

参考图固定用得分最高的那张，只换音频：

| 条件 | 相关 | Δ 基线 |
|---|---|---|
| 电话带宽 300–3400 Hz | 0.322 | +0.008（噪声内） |
| **【基线】我们自己的 TTS** | **0.313** | — |
| 加粉噪 | 0.309 | −0.004（噪声内） |
| 动态范围压平 | 0.226 | −0.088 |
| 换成另一段人声 | 0.219 | −0.094 |
| 停顿拉长（说的字一个没改） | 0.208 | −0.105 |
| 语速 0.85× | 0.182 | −0.131 |
| 语速 1.25× | 0.149 | −0.164 |

**结论反直觉但很干净：**

- **音质不敏感。** 砍到电话带宽、叠上明显的粉噪，读数一动不动 ——
  这个模型对音质相当鲁棒，不用为了它去提升 TTS 采样率或降噪。
- **别去动时间轴。** 变速（快或慢）是掉得最多的一档。
  **不要用 `atempo` 之类去「调语速」**，也不要事后插停顿。
- **原样送进去就行。** 我们现成的 TTS 是这一组里最好的。

> ⚠️ 这里有一条先前的错误结论要更正：在**那张不好的**参考图上测时，
> 换一段外部音频能涨 +0.076，当时判成「音频是第二大因素」。
> 换到好图上重测，同一段外部音频反而掉 −0.094。
> **那是图和音频的交互，不是音频的普遍性质。**
> 教训：在一个本来就烂的工作点上做的归因，不能外推。

## 四、管线不在这个清单里

同一张图、同一段音频、同一个 prompt 和 seed，官方离线管线 **0.140**，
我们的五卡流式 **0.138** —— 差 0.002，噪声底 0.016。**两者无法区分。**

所以口型不准的时候，**先换图，不要先查管线**。
管线那一侧的已知问题和修法见 [lip-sync.md](lip-sync.md)。

## 五、这份实验哪里不够硬

不写这一节的话，上面的数字会显得比实际更确定。

- **每个条件只跑了 1 次**（基线跑了 4 次得出噪声底）。
  Δ 在 0.02–0.04 这一档的几条（眼镜 / 压缩 / 水印 / 手 / 动漫）
  只比噪声底高一点点，**排序不要当真**，只能当「都是小钱」。
- **「杂乱背景」这一条没做成单变量。** 生成那张图时人也被拍远了
  （脸从 229 px 缩到 139 px），而 139 px 这个尺寸本身就对应 0.12–0.15。
  所以它掉的 −0.194 **基本可以由脸变小解释完**，
  「背景乱不乱」这个变量实际上**没测到**。
- **侧脸那条有测量偏差。** 嘴区是按「脸框下三分之一」取的，
  头一转这个位置就偏了。掉分的量级（−0.244 而脸只小 12%）
  说明主体是真的，但具体数字偏悲观。
- 全部走**离线**管线测（为了排除流式自身的影响），
  结论迁到流式上的前提是第四节那条「两者无法区分」。
- 只测了一个人物、一段中文语音。

## 六、自己复现

```bash
# 参考图 → 视频（离线，单卡）
CUDA_VISIBLE_DEVICES=0 torchrun --nproc_per_node=1 \
  minimal_inference/batch_eval.py --single_gpu --num_gpus_dit 1 \
  --ulysses_size 1 --task s2v-14B --size "720*400" --base_seed 420 \
  --training_config liveavatar/configs/s2v_causal_sft.yaml \
  --offload_model True --convert_model_dtype \
  --sample_list 你的.json --prompt "..." --image 图.png --audio 音.wav \
  --infer_frames 48 --load_lora --lora_path_dmd "Quark-Vision/Live-Avatar" \
  --sample_steps 4 --sample_guide_scale 0 --num_clip 10000 \
  --sample_solver euler --ckpt_dir ckpt/Wan2.2-S2V-14B/ --save_dir 出/
```

两个会咬人的地方：

- **真正被读的是 `--sample_list`**，`--image/--prompt/--audio` 只喂给
  提示词扩展那条分支。我第一轮据此判断「sample_list 是死参数」，
  结果三个「变体」跑的全是同一份基线 —— 三个输出文件名都一样才露的馅。
- **输出路径拼接漏了斜杠**：`--save_dir /tmp/x` 得到的是
  `/tmp/xsample_0001_….mp4`，不在 `/tmp/x/` 里。
  盯梢脚本因此报过「没生成 mp4」，**空结果不等于没有**。

打分脚本（纯 Python + ffmpeg + OpenCV，不要 GPU）的做法见第一节，
核心就三步：检人脸 → 取脸框下三分之一 → 和音频包络做互相关。
